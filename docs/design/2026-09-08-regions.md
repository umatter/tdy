# Regions: several tables in one file

*2026-09-08. Step 3 of `docs/design/2026-09-06-members-and-regions.md`, the one
it said to do last and only behind the review gate. A member can now be one
of several tables stacked in a text file or a sheet. Two decisions taken
before writing: stacked tables only, named by ordinal.*

---

## 1. The shape, and how common it is

A file that holds several tables one above the other, separated by blank
lines or rows: a quarterly report with one block per region and a summary
block underneath, a sheet that stacks this year's table on last year's.
Pollock's survey found **188 of 3,712 real CSVs (5.1%)** in this shape, and
CSV is where it is rarest; the literature calls the general case *multiregion
files* and has published detectors for it (Mondrian, PVLDB 2022, taxonomy
**M4**). Today `tdy` reads such a file as one table whose header is the first
block's and whose body runs into the second block's header — a wrong table,
produced confidently, which is the failure this tool exists to refuse.

Out of scope, on purpose: blocks **beside** each other in a sheet. That is a
two-dimensional segmentation (cells as pixels, regions as connected components),
roughly three times the detector for a shape the survey does not count, and it
would add a column window to every identity. A declared `range` already reads
one such block by hand; that stays the answer for it.

## 2. Identity: the ordinal

A region member is `(path, sheet, region)`: three fields, never one string.
The textual form is `report.csv#2` for the second table of a text file and
`book.xlsx#Q1#2` for the second table on sheet `Q1` — read and typed only where
a person does (the report, `_member`, `--accept`, `.accept`, `exclude`,
`validate`, `check --against`), and resolved against the members that exist
exactly as sheet references are: every split of the text is a candidate, and
`MemberRef::resolve` keeps the candidates that exist. The rightmost segment is
a region only if it is a positive integer *and* a member with that region
exists; `Q2` is a sheet, `2` is a region, and a sheet literally called `2` in
a workbook that also has two regions is an ambiguity the resolver names, as it
does today.

**Ordinal, not row window.** The name has to survive the pile's ordinary life,
and a row window does not: a row appended above the second table renames it,
expiring its acceptance and its lock entry, so a growing report re-asks the
same question every month. An ordinal survives that. The rows the block
occupied *when fitted* live in the member's sidecar, where they belong: they
are how this spec reads this file, and the file's hash — which the lock
records — is what tells the world they may have moved. A changed file is
drift, the refit finds the blocks again, and an acceptance carries over by
name and bytes as it does for sheets. Two blocks that swap places swap names,
which is what a person would call that event.

## 3. What a region is, mechanically

A region is a **row window** over the sheet or file, expressed with what the
spec already has:

- A text file: `Extraction::Delimited { .. }` gains `region: Option<RowWindow>`
  — `{ start, end }`, 0-based half-open line numbers of the raw file, applied
  by the extractor *before* anything else, so `skip_rows`, `promote_header` and
  the rest act within the block exactly as they act on a file. The streaming
  executor applies the same window in its reader and keeps streaming: the
  window is a row filter, and rows are independent.
- A sheet: `Extraction::Excel { range }` already reads a block; a region member
  records the window as a `range` whose columns span the used range. Nothing
  new in the extractor.
- Lines, fixed-width and JSON sources have no regions. A log does not stack
  tables, and a JSON document's record arrays are the frame question the JSON
  pointer already answers.

`RowWindow` is validated like a `range`: `start < end`, and the executor
refuses a window that starts past the file's end naming the line — a spec
written for last month's file must not read this month's silently short.

## 4. Detection: blank-row splitting, behind the review gate

`engine::regions_of(path, limits) -> Vec<RowWindow>` splits a text file at runs
of blank lines and a sheet at runs of blank rows (a row is blank when every
cell is), keeps the blocks with at least three rows, and returns their windows
in file order. A file with one block has no regions. The split is
one-dimensional and deterministic; the *judgement* is whether the blocks are
tables of the same kind at all, which a blank row cannot say. So:

| blocks that pass the gates | result |
|---|---|
| none | the ordinary gap report, for the file read whole — unchanged |
| exactly one, and it is the whole file | one plain member — unchanged |
| exactly one, a proper block | one plain member whose spec carries the window, with a note; **no review** — the elimination proved it, as it does for a sheet |
| several | one member per block, each fully fitted on its own, each carrying `review`: "table 2 of 3 in this file, split at blank rows — accept only if it is the same kind of table as the others" |

The last row is the line this page was told to hold. Several sheets that fit
are expanded without review because a sheet name is a fact the file states; a
blank-row boundary is a *reading*, and a person confirms it once per file per
set of bytes, as they confirm a unit shift. The acceptance names the member
and carries over on unchanged bytes and declaration.

Discovery runs where sheet discovery runs, in `report::expand_units`, after
sheets: a sheet member is itself asked for regions, so `book.xlsx#Q1#2` is
reachable. The single-file `fit()` keeps treating the file as one table.

`draft` gains the same split, so a file whose blocks have different headers
drafts each block's columns rather than a merged nonsense, and says which
block each column came from.

## 5. Everything downstream

- **Sidecar**: `<file>#<sheet>#<n>.tdy.toml` or `<file>#<n>.tdy.toml`; the
  fingerprint records `region = n` beside `sheet`. `sidecar_path_for` takes the
  full `MemberRef`, and the old two-argument forms remain.
- **Lock and drift**: `Member.region: Option<u32>`; drift stays per file;
  `Duplicated` and `MixedGranularity` extend to the triple (a file listed whole
  and by region is the same mistake as whole and by sheet).
- **`dataset()`**, the report, `--json`, MCP, `exclude`, `--accept`, the
  console's `.accept`, `validate`, `check --against`: each already resolves a
  `MemberRef` and reads a `sheet`; each reads a `region` beside it. The
  workbench previews a region member as the file with its window highlighted in
  the raw head, and the member title reads `report.csv#2 · rows 41–79`.
- **`source_name`** gains `from = "region"`, the ordinal as a column, for the
  report whose blocks are the periods.

## 6. The rule this keeps

Membership is proved, not discovered at query time. `dataset()` reads a region
member's window from its sidecar and never splits a file itself; a block that
appears, disappears or moves changes the file's hash and is drift with a named
file, and the refit re-splits. A region member never runs until a person has
accepted that its blank-row boundary is a table boundary — unless the split
found exactly one block, which is a proof by elimination, not a judgement.

## 7. Tests

Fixtures (`17_regions.py`): a CSV with three stacked tables of one shape (sums
600.00, 1500.00, 900.00) and a blank line between each; the same as one sheet
of a workbook; a CSV whose second block is a *summary* with a different header
(must be a gap for the declared table, never merged); a CSV with a title block
above the first table (one block after the split — a plain member, no review).

Commit 1 (identity and reading): `MemberRef` with three fields, `name()` and
`resolve()` for the region form; `RowWindow` on `Delimited`, validated and
applied by both executors identically over every text fixture; a hand-written
lock with two region sidecars queries to the sum of both, `_member` naming
`report.csv#1` and `#2`.

Commit 2 (discovery): `regions_of` over the fixtures; the three-table CSV fits
to three members, each `REVIEW`, refused by `dataset()` until each is accepted
by name; acceptance carries over a refit; the summary block is a gap for the
declared table while its siblings fit; the title-block file is one plain
member with a note and no review; the sheet form reaches `book.xlsx#Data#2`;
`draft` names the block each column came from; `exclude = 'report.csv#3'`.
