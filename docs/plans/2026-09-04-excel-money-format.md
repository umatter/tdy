# Excel Money Typing Implementation Plan

> **For agentic workers:** one task; implement it directly, TDD order, then report.

**Goal:** A spreadsheet column whose cells carry a *currency* number format is typed
`Decimal`, not `Float64`, so sibling money columns cannot disagree and no query result
carries IEEE noise where the file shows cents.

**Architecture:** calamine 0.36 parses `numFmts`/`cellXfs` into a stack-local map, keeps
only a 3-variant `CellFormat` enum, and `Cell<T>` carries no style id — so the format is
unreachable through it. Read it ourselves from the xlsx zip instead, exactly as
`src/xlguard.rs` already reads workbook geometry: `xl/styles.xml` gives currency
`numFmtId`s and the `cellXfs` style→format table; the sheet XML's `<c r="D10" s="4">`
gives each cell's column letter and style index. Tally per column; a column whose data
cells are overwhelmingly currency-formatted is money.

**Spec:** `gap_reports/AUDIT_FINDINGS.md`. The defect: `PCA_Report_FY16Q3.xlsx` types
`added` as `decimal(2)` but six structurally identical currency columns as `float64`, so
results show `255871181.10999995` where the sheet shows `255871181.11`.

## Feasibility (already established — do not re-litigate)

Verified against the real file before this plan was written:
- `xl/styles.xml` has `<numFmt numFmtId="164" formatCode="&quot;$&quot;#,##0.00;…">`
  and `numFmtId="44"`; `<cellXfs count="28">` maps style index → numFmtId.
- The sheet XML's cells give column letters and style indices; tallying them yields
  columns D–H at 70/70 currency-formatted cells, A at 0/69, B and C partial (25/69).
- Column letter → index is direct, and `skip_rows`/`promote_header` change rows, not
  columns, so a raw column index equals the final column index on the Excel path.

```rust
/// Sibling columns sharing a currency number format must all type as decimal.
/// PCA_Report_FY16Q3.xlsx typed one as decimal(2) and six as float64, so results
/// carried IEEE noise where the sheet shows cents. Found by the 2026-09-03 audit.
#[test]
fn currency_formatted_columns_all_become_decimal() {
    let f = std::path::Path::new("testdata/xl_money_siblings.xlsx");
    let spec = /* sniff it, as neighbouring tests do */;
    let money: Vec<_> = spec.columns.iter().filter(|c| c.name.starts_with("amount")).collect();
    assert!(money.len() >= 3, "fixture should have several money columns");
    for c in &money {
        assert!(matches!(c.dtype, tdy::spec::DType::Decimal { .. }),
                "{} typed {:?}; sibling money columns must agree", c.name, c.dtype);
    }
}
```

Adapt the call shape to this repo's real `sniff` signature (read neighbouring tests first).
The assertion is the contract.

- [ ] **Step 2: Run it and watch it fail** — the columns come back `Float64`.

- [ ] **Step 3: Implement the format reader.** A function taking the workbook path and a
sheet name, returning the set of column indices whose data cells are currency-formatted:
  - Currency `numFmtId`s: the builtins `5..=8` and `41..=44`, plus any custom `numFmt`
    whose `formatCode` contains a currency symbol (`$`, `€`, `£`, `¥`) or the `[$…]`
    locale-currency construct. Ignore percent and date formats.
  - Parse `<cellXfs>` in document order into a `Vec<numFmtId>` indexed by style index.
  - Stream the sheet XML; for each `<c r="…" s="…">` past the first row, decode the column
    letters to an index and tally (currency_cells, total_cells) per column.
  - A column counts as money when it has cells and ≥80% of them are currency-formatted.
  - Bound the scan; on any parse failure return "no information" and let typing proceed
    unchanged — this is an enhancement, never a new failure mode.
