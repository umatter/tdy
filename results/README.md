# results/ — the evidence behind the paper's numbers

Run outputs, versioned so a reader can check every number the Patterns manuscript reports
without re-running anything. `.gitignore` is an allowlist: a file here is tracked only when it
is named there, so a new run's output stays out until someone decides it belongs.

## pollock/ — tdy on the Pollock data-loading benchmark

Pollock (Vitagliano et al., PVLDB 2023) is 2,290 CSV files, each isolating one deviation from
RFC 4180, scored with Pollock's own `pollock.metrics`. Produced by `scripts/run_pollock.py`
(dataset from `scripts/download_pollock.sh`, scoring in `scripts/_pollock_score.py`), last run
2026-10-01 on the main branch between 0.2.1 and 0.3.0; the summary records no commit.

- `pollock_summary.md` — the table beside Pollock's published systems, per-family scores,
  and tdy's own confidence against the outcome ("wrong while confident", where *wrong* means
  any header, record or cell string differs from the clean file, so formatting counts).
- `pollock_rows_{text,typed}.csv` — per-file metrics; `pollock_confidence_{text,typed}.csv` —
  tdy's confidence per file; `pollock_refused_{text,typed}.txt` — the files it declined.
- The other systems' rows are Pollock's published aggregates, not re-runs.
- Not tracked: `pollock_loaded/` (tdy's converted copies, ~108 MB, regenerated by every run,
  tagged `CACHEDIR.TAG`).

## labeling/ — ground-truth audit of the sniffing tier (2026-09-03, v0.1.0)

148 corpus files in a seeded stratified sample (`labeling_plan.md`, `label_sample_manifest.json`,
`build_labeling_items.py`), each shown to crowd raters beside tdy's reading
(`label_rows.jsonl`); `final_verdicts.json` is the raters' majority verdict per file. The 30
the raters flagged were adjudicated against the actual files (`adjudicate_batch_*.json`,
`adjudication_summary.md`) and the 118 they passed were audited with a checklist
(`verify_batch_*.json`); `verdicts_all.py` records the complete audit: every misread with its
kind, tdy's confidence and whether a note fired, plus the ambiguous and degraded files.
`fresh_*` is a disjoint sample drawn 2026-09-04 for a re-check; `flagged_batch_*` are the
flagged items' readings. `live_backend.out` is the live model-tier test run of 2026-09-03 (v0.1.0).

The audit found five misreads among the flagged files, one of them silent at confidence 0.80
(valid UTF-8 read as windows-1252), which 0.2.0 fixed (`CHANGELOG.md`, "Fixed — silent wrong
values"). The numbers here describe v0.1.0 and have not been re-measured since.

Not tracked: the Prolific study records (`subs.json`, `annotator_stats.json`, `study.json`,
`probe_*`, `resp_probe.out`). They carry participant identifiers and are never published; the
votes in the tracked files carry none.

## corpus_sweep/ — the 26-repository corpus sweep

Outputs of `TDY_CORPUS=corpus cargo test --release --test corpus -- --nocapture`
(`tests/corpus.rs`), one file per run, dated in the name or the header: the survey of how
many files are read confidently, read unsure, or declined, and why. The sweep exercises the
heuristic tier only (no declared target), and its reproducibility check compares row count,
column count and schema across two executions. `corpus_csv_confidence_2026-10-01.tsv` is the
per-file confidence of every CSV/TSV at that run; `summary_sweep.json` and `skip_sweep.json`
are the summary-row and skip-row sweeps. The corpus itself (`corpus/`, ~7 GB) is fetched by
`scripts/download_corpus.sh`; the commits it fetched are recorded in
`corpus/00_catalog/REPO_COMMITS.tsv`.
